# MyApplication — бизнес-логика

Этот сайт описывает **бизнес-логику** приложения MyApplication: какие сценарии
использования (use cases) оно реализует, какие правила и ограничения в них
заложены и какой контракт эти сценарии предоставляют вызывающей стороне.

Технические и эксплуатационные детали (как собрать, запустить, задеплоить,
где смотреть логи/трейсы) документированы отдельно — в
[`README.md`](https://github.com/rualert/my-application/blob/master/README.md)
и [`CLAUDE.md`](https://github.com/rualert/my-application/blob/master/CLAUDE.md)
корневого репозитория, чтобы не дублироваться и не расходиться с ним.

## Как устроена бизнес-логика в коде

Приложение следует принципам Clean Architecture: вся бизнес-логика (use case'ы,
правила, DTO) живёт в слое `MyApplication.Application`, независимом от веб-фреймворка
и внешних систем. Слой `MyApplication.Api` — это только точка входа (HTTP-контроллеры),
которая вызывает use case'ы из `Application`, но не содержит бизнес-правил сама.
Слой `MyApplication.Infrastructure` реализует интеграции с внешними системами
(на момент написания — пуст, интеграций ещё нет) и подставляется в `Application`
через интерфейсы (Dependency Inversion).

Документация на этом сайте организована по **сценариям использования** (по одному
разделу на каждый) — см. дерево в боковом меню слева.

## Текущий статус

Сейчас в приложении реализован один сценарий — [«Прогноз погоды»](/weather-forecast/overview) —
и он является демонстрационным (placeholder), доставшимся от шаблона ASP.NET Core,
а не реальной бизнес-функцией продукта. По мере появления настоящей бизнес-логики
разделы здесь должны добавляться и обновляться вместе с кодом.
