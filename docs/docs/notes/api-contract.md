# Контракт API

Реализовано в `NotesController` (`src/MyApplication/MyApplication.Api/Controllers/NotesController.cs`).

## Эндпоинты

| Метод и путь | Описание | Успех | Ошибки |
|---|---|---|---|
| `POST /Notes` | Создать заметку | `201 Created` + заметка | `400` — нарушены правила заголовка/текста |
| `GET /Notes` | Список всех заметок (без текста), от новых к старым | `200 OK` + массив | — |
| `GET /Notes/{id}` | Заметка целиком по идентификатору | `200 OK` + заметка | `400` — не найдена |
| `PUT /Notes/{id}` | Обновить заголовок и текст заметки | `200 OK` + заметка | `400` — не найдена, либо нарушены правила |
| `DELETE /Notes/{id}` | Удалить заметку | `204 No Content` | `400` — не найдена |

`{id}` — GUID.

Заметка «не найдена» и нарушение бизнес-правил намеренно возвращают один и тот же код
(`400`) — оба случая являются подклассами общего `DomainException`, который глобально
маппится на 400 Bad Request одним обработчиком, без разбора по типу в каждом
конкретном методе контроллера. Различать причину можно по тексту сообщения в теле
ответа.

## Тела запросов

`POST /Notes`, `PUT /Notes/{id}`:

```json
{
  "title": "Заголовок",
  "text": "Текст заметки"
}
```

## Тела ответов

Полная заметка (`POST`, `GET /Notes/{id}`, `PUT`):

```json
{
  "id": "d982562b-6d60-4cf0-8820-e1d577837650",
  "title": "Заголовок",
  "text": "Текст заметки",
  "createdAt": "2026-09-16T15:49:33.12Z",
  "updatedAt": "2026-09-16T15:49:33.12Z"
}
```

Краткие сведения в списке (`GET /Notes`) — без поля `text`:

```json
[
  {
    "id": "d982562b-6d60-4cf0-8820-e1d577837650",
    "title": "Заголовок",
    "createdAt": "2026-09-16T15:49:33.12Z",
    "updatedAt": "2026-09-16T15:49:33.12Z"
  }
]
```

При `400 Bad Request` тело ответа — текст с описанием причины, например:
`Заголовок заметки не может быть длиннее 1024 символов.` (нарушение
[правил](./business-rules)) или `Заметка с идентификатором ... не найдена.`
