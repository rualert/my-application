# Контракт API

Реализовано в `NotesController` (`src/MyApplication/MyApplication.Api/Controllers/NotesController.cs`).

Все эндпоинты требуют заголовок `Authorization: Bearer <accessToken>` (см.
[«Авторизация»](/auth/overview)) — заметки скоупятся по вызывающему
пользователю из токена, отдельного параметра для этого в запросах нет.

## Эндпоинты

| Метод и путь | Описание | Успех | Ошибки |
|---|---|---|---|
| `POST /Notes` | Создать заметку (владелец — вызывающий пользователь) | `201 Created` + заметка | `400` — нарушены правила заголовка (слишком длинный)/текста; `401` — не залогинен |
| `GET /Notes?from=&count=` | Страница списка **своих** заметок (без текста), от новых к старым | `200 OK` + массив | `400` — невалидные `from`/`count`; `401` — не залогинен |
| `GET /Notes/{id}` | Заметка целиком по идентификатору | `200 OK` + заметка | `400` — не найдена; `401` — не залогинен; `403` — принадлежит другому пользователю |
| `PUT /Notes/{id}` | Обновить заголовок и текст заметки | `200 OK` + заметка | `400` — не найдена, либо нарушены правила; `401` — не залогинен; `403` — принадлежит другому пользователю |
| `DELETE /Notes/{id}` | Удалить заметку | `204 No Content` | `400` — не найдена; `401` — не залогинен; `403` — принадлежит другому пользователю |

`{id}` — GUID.

## Пагинация списка

`GET /Notes` принимает два необязательных параметра запроса:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `from` | `0` | Сколько заметок пропустить с начала списка (после сортировки от новых к старым) |
| `count` | `50` | Сколько заметок вернуть |

`from` не может быть отрицательным, `count` должен быть положительным — иначе `400`.
Если `from` выходит за пределы списка, возвращается пустой массив.

Заметка «не найдена» и нарушение бизнес-правил намеренно возвращают один и тот же код
(`400`) — оба случая являются подклассами общего `DomainException`, который глобально
маппится обработчиком без разбора по типу в каждом конкретном методе контроллера.
Различать причину можно по тексту сообщения в теле ответа. `401`/`403`, в отличие
от этого, разбираются по конкретному типу исключения и **не** смешиваются с `400`
(см. [«Авторизация»](/auth/overview)).

## Тела запросов

`POST /Notes`, `PUT /Notes/{id}`:

```json
{
  "title": "Заголовок",
  "text": "Текст заметки"
}
```

`title` необязателен: его можно опустить, передать `null`, `""` или строку из
одних пробелов — во всех этих случаях заметка сохраняется без заголовка
(см. [правила](./business-rules)). `text` обязателен.

## Тела ответов

Полная заметка (`POST`, `GET /Notes/{id}`, `PUT`):

```json
{
  "id": "d982562b-6d60-4cf0-8820-e1d577837650",
  "title": "Заголовок",
  "text": "Текст заметки",
  "createdAt": "2026-09-16T15:49:33.12Z",
  "updatedAt": "2026-09-16T15:49:33.12Z"
}
```

У заметки без заголовка в ответе `"title": null` (это относится и к списку ниже).

Краткие сведения в списке (`GET /Notes`) — без поля `text`:

```json
[
  {
    "id": "d982562b-6d60-4cf0-8820-e1d577837650",
    "title": "Заголовок",
    "createdAt": "2026-09-16T15:49:33.12Z",
    "updatedAt": "2026-09-16T15:49:33.12Z"
  }
]
```

При `400 Bad Request` тело ответа — текст с описанием причины, например:
`Заголовок заметки не может быть длиннее 1024 символов.` (нарушение
[правил](./business-rules)) или `Заметка с идентификатором ... не найдена.`
